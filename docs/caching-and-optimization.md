# Caching and optimization

| Layer | Reuse / invalidation | Constraint |
| --- | --- | --- |
| Process client | `_CLIENT` reuses the configured optional client during one process. | Environment settings are read on import/startup; restart for changes. |
| Bulk progress index | Retains exact-unique units and processed-input state for resume. | Content fingerprints, the input set, cache version, and cleaning settings must match. Changes rebuild with a warning; `--no-resume` also rebuilds. |
| Flat-JSON unit vector index | Reused by `novelty`; `index --name` writes a named index. | Models and vector dimensions must be compatible. Keep historical vectors unchanged unless rebuilding is explicitly intended. |
| Generated repository indexes | Static source metadata, regenerated by `scripts/generate_repo_docs.py`. | `--check` detects drift; these indexes do not contain embeddings. |

Canonicalized text hashes remove exact duplicates. Lexical merge/novelty use
upper-bound checks before full sequence matching. Bulk embedding requests are
batched and use configured host concurrency. Semantic clustering still compares
representatives with prior clusters, so worst-case work is quadratic. No benchmark
claims a speedup from this audit.

For a local profile, use a disposable corpus and disable embeddings first:

```bash
python3 -m cProfile -s cumulative distill_offline.py bulk /path/to/disposable-corpus --no-semantic --no-resume
```

Compare retained text, provenance, duplicate counts, and output determinism before
accepting a performance change. Do not remove assertions or meaningful tests to
improve runtime. No background indexer or automatic cache-reset job is installed.
